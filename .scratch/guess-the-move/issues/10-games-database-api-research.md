## Question

What game database(s)/API(s) can serve the Plenum Selection Phase's live "find matching games" step — searching by criteria such as the reached opening, tournament tier (e.g. world championship), and player gender — with latency low enough for live use during a Session? Do any of them also expose enough per-move engine analysis (or raw PGN suitable for feeding an engine) to compute an Accuracy Score, or does that require a separate analysis pass after fetching a candidate?

Candidates worth checking: Lichess (opening explorer / masters database / study & game export APIs), Chess.com (published-data API), and any curated/offline game datasets that could be bundled instead of hit live.

## Answer

Lichess's Masters DB Opening Explorer (`explorer.lichess.org/masters`) is the best fit for the live, reached-position search step: it supports `fen`/`play` position lookup with a `since`/`until` year range, returns up to 15 real top games (with player names, ratings, year, result) per query, runs on a dedicated service sized for ~12k requests/minute, and has no documented per-key rate cap for this endpoint — comfortably fast enough for live use. However, it does **not** support filtering by tournament tier or player gender, and neither does anything else surveyed. Tier has to be derived client-side by fetching each candidate's PGN (`/masters/pgn/{gameId}`) and matching its `Event` tag against a tier table the app curates itself. Gender has to come from an offline join against FIDE's official ratings list (`ratings.fide.com`, which has a real `sex` field), matched by player name/FIDE ID — no PGN source or chess API (Lichess or Chess.com) carries a gender field. Chess.com's Published-Data API has no position-search surface at all — only player/title-scoped archives — so it cannot serve the live search step, though its archives (and TWIC's/PGN Mentor's/Lumbra's Gigabase's downloadable PGNs) are viable raw material to bundle if `lila-openingexplorer` is ever self-hosted instead of hit live (it's open-source and built for exactly this). On evaluations: no source gives ready-made per-move engine analysis for arbitrary OTB games — Lichess only has opportunistic evals for previously-analyzed Lichess-hosted games and a large-but-partial FEN→eval cache (~410M positions, good for common openings, not guaranteed deep into an obscure game) — so every Candidate Game's Accuracy Score requires a separate engine analysis pass over its fetched PGN (per issue 17's Stockfish integration), regardless of which database supplies the game. Full detail, endpoints, parameters, and citations: [research/games-database-api.md](../research/games-database-api.md).

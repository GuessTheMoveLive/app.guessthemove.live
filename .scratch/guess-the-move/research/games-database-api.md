# Games database API — research

Research for [issue 10](../issues/10-games-database-api-research.md). Question: what can serve the Plenum Selection Phase's live "find a Candidate Game" step — searching by reached position, tournament tier, and player gender, in seconds — and does any source already carry per-move engine evaluation, or does an Accuracy Score always require a separate engine pass?

## 1. Lichess

### 1a. Opening Explorer — Masters database

**Endpoint:** `GET https://explorer.lichess.org/masters` (self-hosted service, separate host from `lichess.org`). Query params, straight from the OpenAPI spec: `fen` (root position), `play` (comma-separated UCI moves from `fen`), `since`/`until` (**year** granularity, default `since=1952`), `moves` (how many candidate next-moves to list, default 12), `topGames` (how many top games to list, default 15, **max 15**). ([lichess-org/api spec, `masters.yaml`](https://github.com/lichess-org/api/blob/master/doc/specs/tags/openingexplorer/masters.yaml))

Response (confirmed via the spec's own example) is aggregate stats keyed by the position: win/draw/loss counts, a `moves[]` list each with `uci`/`san`/`averageRating`/result counts and (for the rarest continuations) a single linked `game`, plus a `topGames[]` list of up to 15 real games. Each game reference is only:
```json
{ "id": "kN6d9l2i", "winner": "black",
  "black": { "name": "Anand, V.", "rating": 2785 },
  "white": { "name": "Carlsen, M.", "rating": 2881 },
  "year": 2014, "month": "2014-06" }
```
([`OpeningExplorerMasters.yaml`](https://github.com/lichess-org/api/blob/master/doc/specs/schemas/OpeningExplorerMasters.yaml) / example](https://github.com/lichess-org/api/blob/master/doc/specs/examples/openingExplorer-masters.json.yaml)) — **no tournament/event name, no round, no time control, and no gender field anywhere in the response.** There is also no query parameter for event/tournament tier or player gender/title — the only filters are the position itself and a year range. To get the actual tournament name (PGN `Event`/`Site`/`Round` tags) you must make a second call, `GET https://explorer.lichess.org/masters/pgn/{gameId}`, which returns the raw PGN of that one OTB game (`application/x-chess-pgn`) — nothing else. ([`masters-pgn-gameId.yaml`](https://github.com/lichess-org/api/blob/master/doc/specs/tags/openingexplorer/masters-pgn-gameId.yaml)) So: **tier filtering ("was this a World Championship match") is only possible client-side, by fetching each candidate's PGN and pattern-matching the `Event` tag text — the search API itself cannot filter by it.** Same conclusion for gender: it's simply absent from both the search response and the PGN standard tags Lichess returns.

The Masters DB's source data is **Gorgobase**, an aggregation of TWIC (The Week in Chess) PGNs for modern games plus pgnmentor.com PGNs for older/historic games, restricted to OTB games of FIDE 2200+-rated players from 1952 onward, per Lichess's own community team explaining it on the forum. ([Lichess Feedback: "Masters Database - where is the actual source..."](https://lichess.org/forum/lichess-feedback/masters-database-where-is-the-actual-source-and-is-there-any-way-to-contribute-more-games)) That means the Masters DB is, in effect, a pre-merged, pre-indexed, queryable-by-position mirror of exactly the same TWIC/PGN-Mentor raw material discussed in §3 below — using Lichess's live API buys you server-side position search over that corpus "for free," at the cost of the filtering gaps just described.

### 1b. Opening Explorer — Lichess (online) games & Player games

`GET https://explorer.lichess.org/lichess` (aggregated **online, mostly amateur** rated games from Lichess's own userbase) adds `speeds`, `ratings` (bucketed groups), `since`/`until` at **month** granularity, `topGames` (max 4), `recentGames` (max 4–8), `history`. ([`lichess.yaml`](https://github.com/lichess-org/api/blob/master/doc/specs/tags/openingexplorer/lichess.yaml)) `GET https://explorer.lichess.org/player` streams (NDJSON) a single named player's own games filtered by position/color/speed/mode/date. ([`player.yaml`](https://github.com/lichess-org/api/blob/master/doc/specs/tags/openingexplorer/player.yaml)) Neither adds a tournament-tier or gender filter either, and — being Lichess's online player pool, not curated OTB events — neither is a good source for "was this a World Championship match" in the first place. Not relevant to this app's Candidate Game criteria beyond confirming the same gaps.

### 1c. Game export & engine evaluations

`GET /game/export/{gameId}` (on `lichess.org`, for games **played on Lichess itself** — a different ID space from Masters DB game IDs) supports `evals=true` — "Include analysis evaluations and comments, **when available**" as PGN `%eval` comments or an `analysis` JSON field — and `accuracy=true`, Lichess's own per-player accuracy-percent metric, "**Only available in JSON**." ([`game-export-gameId.yaml`](https://github.com/lichess-org/api/blob/master/doc/specs/tags/games/game-export-gameId.yaml)) Crucially, **evals are only present if that specific Lichess game was previously analyzed** (a player requested "Analysis board" on it) — this is opportunistic, not guaranteed, and it only applies to Lichess-hosted games, never to Masters DB (real OTB) games, whose `/masters/pgn/{gameId}` response is bare PGN with no eval data at all. A companion bulk endpoint, `POST /games/export/_ids` (up to 300 IDs, `evals`/`accuracy` params too), works the same way but again only for Lichess-hosted game IDs. ([`api-games-export-_ids.yaml`](https://github.com/lichess-org/api/blob/master/doc/specs/tags/games/api-games-export-_ids.yaml))

Separately, Lichess publishes a standing **evaluations dataset** (`lichess_db_eval.jsonl.zst`, keyed by FEN, "**409,710,113** chess positions evaluated with Stockfish" as of the September 2026 dump) as a downloadable bulk file, not a live per-game API. ([database.lichess.org](https://database.lichess.org/)) It's large but opportunistic/crowd-sourced (positions users happened to analyze), so it's a poor fit for guaranteeing coverage of every move of an arbitrary historical Masters-DB game — a popular Najdorf line from move 1–10 will very likely be in it; move 35 of an obscure 1978 Soviet Championship game very likely will not.

**Conclusion for Lichess: no source here gives ready-made, guaranteed per-move evaluation for an arbitrary OTB Candidate Game.** A fetched Masters-DB game's PGN always needs a separate engine analysis pass (the app's own Stockfish integration, per [issue 17](../issues/17-chess-engine-choice-hosting.md)) to compute the Accuracy Score.

### 1d. Rate limits

General policy, stated directly in the API's intro docs: "All requests are rate limited using various strategies... **Only make one request at a time.** If you receive an HTTP response with a **429** status, you have exceeded one of the rate limits. In most cases, waiting one minute before retrying will be sufficient." ([lichess-org/api spec, top-level description](https://github.com/lichess-org/api/blob/master/doc/specs/lichess-api.yaml)) The Opening Explorer runs on its own dedicated Rust/RocksDB service (`lila-openingexplorer`), separate from the main `lichess.org` rate limiter, sized to "handle around **12k requests/minute**" in production per its own README — a healthy, real-time-friendly budget for a single event's occasional lookups. ([lichess-org/lila-openingexplorer README](https://github.com/lichess-org/lila-openingexplorer/blob/master/README.md)) In practice the service has had full outages returning blanket 429s ([lila issue #19610, "Complete outage of explorer.lichess.ovh"](https://github.com/lichess-org/lila/issues/19610)) — worth a client-side fallback/retry, but not evidence of a restrictive per-app quota; there's no documented per-key request cap for the Explorer specifically, unlike the separately-documented Cloud Eval endpoint's 3,000/day/IP limit noted in the sibling [chess-engine-hosting research](chess-engine-hosting.md).

**`lila-openingexplorer` is itself fully open-source and self-hostable** — it explicitly supports importing PGN dumps (including `database.lichess.org` dumps, and by extension TWIC/PGN Mentor files) directly into its own RocksDB index and serving the same `/masters`, `/lichess`, `/player` API shape locally. ([lila-openingexplorer README, "Import games"](https://github.com/lichess-org/lila-openingexplorer/blob/master/README.md)) This is a credible fallback if the public `explorer.lichess.org` ever proves too unreliable for a live event: self-host the same server against a bundled TWIC/PGN-Mentor corpus, eliminating both the outage risk and the external-network dependency during a Session.

## 2. Chess.com Published-Data API

Per Chess.com's own docs, the entire API is **read-only, player- or title-scoped, with no position/search surface at all**: "The API does not support searching or filtering games by position/opening (FEN), tournament tier, or player characteristics" — the only ways to reach a game are by player (current game, monthly archive, archive-by-time-control) or by resolving a tournament/match URL you already have. ([Chess.com: Published-Data API](https://www.chess.com/news/view/published-data-api)) There is **no opening-explorer-equivalent** and **no way to ask "give me games that reached this FEN."** To use Chess.com data for this app's Candidate Game search you would have to already know which players/tournaments to pull archives from and scan the returned PGNs client-side for the target position yourself — that's not "seconds," it's a bulk-download-and-grep problem, disqualifying it as the *live* search step.

Game objects do carry useful fields once you have them — `pgn`, `tournament` (a URL, not a structured tier/category value), `match` (URL), `eco` (URL), `rated`, `time_class`/`time_control`, `rules` — per the field list in the same doc. **No per-move engine evaluation field exists anywhere in the schema.** ([Chess.com: Published-Data API](https://www.chess.com/news/view/published-data-api))

There is one gender-adjacent surface: `GET https://api.chess.com/pub/titled/{title-abbrev}` lists usernames holding a given title, and the valid abbreviations include women's titles — **"GM, WGM, IM, WIM, FM, WFM, NM, WNM, CM, WCM."** ([Chess.com: Published-Data API](https://www.chess.com/news/view/published-data-api)) That's a usable *proxy* for "games by a woman titled player" (fetch the `WGM`/`WIM`/`WFM`/`WCM`/`WNM` lists, then pull those players' archives) but it is **not a gender field on games or players**, it only covers players who hold a women's-only title (excluding untitled women and women holding open titles like plain GM/IM), and it still requires the same client-side archive-scan-for-position problem above.

**Rate limits/caching:** "Serial access is unlimited. Parallel requests may trigger rate limiting, resulting in a 429." Responses carry `ETag`/`Last-Modified` for conditional `304` requests, and "**Endpoints refresh at most once every 12 hours**" server-side. ([Chess.com Help Center: Published-Data API](https://support.chess.com/en/articles/9650547-published-data-api)) The 12-hour refresh window is irrelevant here (we're searching historical games, not live ones), but it underlines that this API was designed for profile/archive browsing, not low-latency structured search.

**Conclusion: Chess.com's API cannot serve the live "search by reached position" step at all** — it has no position search, no tournament-tier filter, and no true gender field, only a title-list proxy. It's a plausible *data source* to bundle into a self-hosted corpus (its monthly archives are downloadable PGN), but not a live query surface for this use case.

## 3. Offline/bundleable game datasets

All three below share the same shape: downloadable PGN (sometimes also ChessBase/Scid binary formats), **no live search API**, standard PGN header tags only (`Event`, `Site`, `Round`, `White`, `Black`, `WhiteElo`, `BlackElo`, `ECO`, `Result`) with **no structured tournament-tier or gender field** — any tier/gender filtering has to be derived by the app itself, either by string-matching `Event` text or by joining player names against an external metadata source (see the FIDE list below).

- **TWIC (The Week in Chess):** weekly PGN + ChessBase digests published every Monday (issue 1663 dated 21 Sep 2026 alone carries 10,030 games), covering top international events (Olympiad, national championships, opens, and online supertournaments like Titled Tuesday). ([theweekinchess.com/twic](https://theweekinchess.com/twic)) Licensing is a real constraint: "**TWIC magazine is free for personal use only. All rights are reserved.**" A one-off ~£30 donation unlocks a bundled historical archive of "over 4 million games." No search API — it's zipped PGN files requiring local parsing/indexing (this is exactly the raw material Lichess's own Masters DB is built from, per §1a).
- **PGN Mentor:** "The files below are available for download, completely free," organized by player, by opening family, and by event/tournament (1976–2024). ([pgnmentor.com/files.html](https://www.pgnmentor.com/files.html)) Filenames carry no tier or gender metadata beyond the player/event name itself; it's the second half of the Gorgobase blend behind Lichess's Masters DB.
- **Lumbra's Gigabase:** a currently-maintained, free, large aggregate — "over 10.3 million over-the-board games" plus "over 7.2 million curated online games (Elo 1800+)," distributed as PGN or Scid, "updated regularly on the first Tuesday of every month." ([lumbrasgigabase.com/en](https://lumbrasgigabase.com/en/)) Licensed **CC BY-NC-SA 4.0 — non-commercial only**, which is a real constraint if this project is ever monetized. No tier/gender field; ECO and Elo are the only structured filters offered by the site's own tooling. (Caissabase, once a popular free alternative, appears to be defunct as of 2025 — its site is down; Lumbra's Gigabase and pgnmentor.com are the live, actively-maintained free options as of this research.)

**Gender, concretely:** none of the PGN-based sources above carry a gender tag, and neither do Lichess or Chess.com. The one official, structured, primary source that does is **FIDE's own downloadable ratings list** — `https://ratings.fide.com/download/players_list_xml.zip`, whose per-player XML record includes `fide_id`, `name`, `country`, `title`, `rating`, and **`sex`** (`M`/`F`). ([FIDE: Download latest official FIDE Rating list](https://ratings.fide.com/download_lists.phtml)) To filter Candidate Games by gender against any of TWIC/PGN Mentor/Lumbra's Gigabase/Lichess Masters DB, the realistic path is: **bundle the FIDE ratings list offline, join it against `White`/`Black` PGN tags by name (and ideally FIDE ID, where the PGN carries `WhiteFideId`/`BlackFideId`), and pre-tag each game's player-gender at ingest time** rather than expecting any live query parameter to do it.

**Tournament tier, concretely:** same story — no source exposes a "tier" enum. The practical approach is a small **curated tier list/keyword table the app maintains itself** (e.g. mapping `Event` strings like "World Chess Championship 2021", "Tata Steel Chess Masters", "FIDE Candidates" to a tier), applied at ingest against whichever corpus is bundled — this is a modeling decision for the app, not something any of these sources will do for you.

## 4. Engine evaluation summary (answering the ticket's 4th question directly)

No source surveyed exposes ready-made, complete per-move engine evaluation for arbitrary OTB games:
- **Lichess Masters DB PGN** (`/masters/pgn/{gameId}`): bare PGN, no evaluations, ever.
- **Lichess game export `evals=true`**: only for Lichess-hosted games that were previously analyzed on-site, and only "when available" — not guaranteed, and doesn't apply to OTB Masters DB games at all.
- **Lichess evals dataset** (`lichess_db_eval.jsonl.zst`): a large but opportunistic FEN→eval cache (~410M positions); usable as a cheap first-pass lookup for common opening positions, but cannot be relied on for full move-by-move coverage of an arbitrary historical game deep into the middlegame/endgame.
- **Chess.com**: no evaluation field anywhere in its schema.
- **TWIC / PGN Mentor / Lumbra's Gigabase**: raw PGN only, no evaluations.

**Every path to a Candidate Game's Accuracy Score requires a dedicated engine analysis pass over the fetched PGN** (the app's own Stockfish integration per [issue 17](../issues/17-chess-engine-choice-hosting.md) / [chess-engine-hosting research](chess-engine-hosting.md)), optionally short-circuited move-by-move by first checking the Lichess evals dataset for a cache hit on well-known opening positions before falling back to a live engine call.

## Recommendation

**Use the Lichess Masters DB Opening Explorer (`explorer.lichess.org/masters`) as the live, position-based search step** — it is the only source among those surveyed that supports true reached-position search with sub-second-scale responses and a generous, effectively unthrottled request budget for a single event (§1d), returning up to 15 real top games per query already ranked by player strength. Accept its two hard gaps rather than expecting the API to close them: **(a) tournament-tier filtering must happen client-side** by fetching each candidate's PGN (`/masters/pgn/{gameId}`) and matching its `Event` tag against a small tier table the app curates itself, and **(b) gender filtering must happen via an offline join against FIDE's official ratings list** (`ratings.fide.com`, which has a real `sex` field) matched by player name/FIDE ID, since no gender field exists in Lichess, Chess.com, or any PGN archive. Chess.com's Published-Data API should be ruled out for the live search step entirely — it has no position search surface at all (§2). If `explorer.lichess.org`'s public availability ever proves a liability for a live event, `lila-openingexplorer` is open-source and self-hostable against a bundled TWIC + PGN Mentor corpus (§1a, §1d), which would also remove the external-network dependency and any residual rate-limit risk, at the cost of standing up and periodically re-importing that index yourself. In every case, computing the Accuracy Score requires a separate engine analysis pass over the fetched PGN (§4) — no surveyed source supplies ready-made per-move evaluations for arbitrary OTB games.
